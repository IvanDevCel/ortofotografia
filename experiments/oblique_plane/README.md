# Oblique camera on a plane: isolated experiment

Scope: synthetic still images only, with nominal gimbal inclinations 0°, 15°, 30° and 45°. No flights, Gazebo changes, PX4 output, second rangefinder or elevation model. The operational source files are unchanged in this worktree and in the original workspace.

`baseline_manifest.json` identifies the frozen functional snapshot, original dirty-workspace state and SHA-256 of source/resource files. Shared TIFFs, weights and existing indices are read from that original workspace; the experiment uses its existing Python/CUDA environment. Only files beneath this experiment's `outputs/` are generated by the pipeline, aside from this report.

## Cases and comparison

36 cases: 16 mapped-land views, 8 mapped-water views, 8 water images searched against a geographically disjoint map, and 4 uniform-water controls. Inputs contain noisy body attitude, measured gimbal angles, a valid synthetic height with stated uncertainty, capture time, calibration and static EKF origin. They do not contain the current true latitude/longitude or true camera/body pose.

`generate.py` stores known camera and fuselage latitude, longitude, altitude relative to the simulation datum, AGL and orientation separately in `truth_evaluation_only.json`. `run.py` never opens that file. `evaluate.py` reads it only after predictions exist. Altitude datum is the artificial plane z=0, not real surveyed AMSL. Optical camera axes are right/down/forward; body axes are forward/right/down. Full matrices and quaternions are primary; Euler angles are explicitly labelled.

The baseline is the frozen operational temporal localizer, with temporal state reset for each independent image. It receives the oblique image without gimbal adaptation. This is a direct compatibility reference, not a matched-hardware flight A/B study. The candidate reuses frozen models/features/index code and adds a plane-based gimbal transform, footprint-aware rectification, original-point planar PnP, spatial inlier checks, pose consistency, ambiguity rejection and approximate sensor-error propagation.

The prototype processes every top-10 candidate without the baseline's 0.9-second deadline; latency is reported rather than hidden. No conclusion about real-time suitability is allowed unless it meets that budget. Synthetic noise specifications are declared in `config.json` and are not hardware specifications. No thresholds are tuned after looking at evaluation truth.

## Reproduce in Windows

Use the original workspace's `para_github/.venv/Scripts/python.exe`, set `PYTHONDONTWRITEBYTECODE=1` and `PYTHONIOENCODING=utf-8`, and run, from this directory:

```text
python test_geometry.py
python generate.py
python run.py
python evaluate.py
```

The source workspace is obtained from `baseline_manifest.json`. Models and indices must already be installed. Estimated runtime for generation and 36 paired trials is 2–5 minutes on the RTX 5080, dependent on caching. Failed/rejected detections are retained; there is no fallback that copies reference truth into estimates.

The current functional version, flight routing, live viewer and sensor SDFs are not modified. This experiment does not authorize or launch a new flight.
